# 虚拟跑步 1.4.8：电脑模拟器每日晨跑

北京时间每天 07:00 开始，08:00 停止位置发送并自动操作安小信结束。速度 12 km/h，环形半径 150 米，一小时预计约 12 公里。应用启动动画和定位采样会使实际时长、里程与理论值略有差异。结束确认也需要几秒至几十秒。

## 文件

- morning_run.py：晨跑脚本，完整版通过界面配置后使用包内 Python 运行。
- 晨跑配置.json：时间、速度、半径、SDK、AVD 和允许的起点区域。
- 检查晨跑环境.cmd：只读检查，不开始跑步，不发送位置。
- 试跑60秒.cmd：立即试跑 60 秒，自动开始、发送路线并结束；不改变当天的定时状态。
- 启用每日晨跑.cmd：注册当前 Windows 用户的每日计划任务。
- 停用每日晨跑.cmd：停止未来的定时执行，不强制中断已经开始的记录。
- logs：每次运行的日志、坐标轨迹、系统定位和结果截图。
- daily-state.json：当天运行状态；failed 表示未完成，finished 表示脚本确认了结束流程，不等于服务端最终认可运动数据。

## 第一次设置

1. 解压完整软件包，双击“启动虚拟跑步.cmd”，在“首次安装”准备 Android 环境。在模拟器中安装并登录安小信 2.0.5。原 APK 在该模拟器中需要 x86 安装方式，电脑版软件的安装按钮已处理。
2. 先正常结束已有记录。脚本可从已识别的首页自动进入运动页面，也会复用已有“开始运动”页面。
3. 如果在模拟器中使用过安卓版虚拟跑步，先点击它的“恢复真实定位”。自动脚本采用电脑 geo fix 接口。
4. 确认 Windows 当前时区为北京，在“晨跑与登录”点击“读取当前 GPS 起点”并确认位置，设置速度和半径，点击“保存并检查环境”。“跑步测试”现为自动读取起点的一键流程，不需手填坐标。
5. 检查成功后点击“保存并启用每日晨跑”。任务名称是 VirtualRun-Morning-0700。06:55 准备，07:00 才点击开始运动，08:00 停止发送并结束。

电脑需要保持开机、当前用户已登录，安小信保持登录且网络可用。配置会请求 Windows 唤醒休眠设备，但能否唤醒取决于设备及唤醒计时器设置；关机不会执行。参考 [Microsoft 计划任务设置](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset)。

完整版自带 Python，换电脑无需另装 Python。请通过软件重新保存个人配置，软件会填写该电脑的运行环境和 SDK 路径。包内 morning 文件夹提供脚本和配置模板；启用前必须由界面生成“晨跑配置.json”，不要直接运行未配置的模板。

配置、日志及可双击的检查/启用/停用命令位于 %LOCALAPPDATA%\VirtualRunDesktop\morning，可以点击“打开配置与日志”查看。旧的独立晨跑脚本包仍需本机 Python；本说明推荐使用 1.4.8 完整版界面配置。

不要在晨跑时同时使用电脑版定位工具或安卓版定位软件发送另一条路线。移动或删除完整软件包前先停用任务；改到新目录后在软件中重新保存配置并启用，应用会更新自己登记的同名任务。

## 后台模拟器

在软件“晨跑与登录”勾选“后台运行模拟器”并保存配置或启用每日晨跑后，晨跑脚本会用无窗口方式启动指定 AVD。脚本通过 ADB 读取安卓内部控件和点击按钮，不依赖桌面窗口位置或鼠标焦点。首次隐私、登录权限和起点确认先在可见窗口完成。

已经启动的模拟器不会被重启或改成另一显示模式。改为后台前先结束已有记录、正常关闭模拟器；恢复窗口时先点击电脑版“关闭模拟器”，再取消勾选启动。脚本结束记录后会保留后台模拟器进程。电脑需要保持开机、不休眠且 Windows 用户已登录。

## 起点确认

优先从当时系统 GPS 开始；无 GPS 时，在记录开始前静止准备配置中的 anchor_wgs84。允许距自己保存的起点 2000 米以内的当前位置。检测到美国默认 GPS 等远距离位置时跳过当天任务，请先在电脑版中准备正确起点。不要直接把百度地图 BD-09 坐标填入配置。

## 失败与停止

已有跑步记录、登录失效、界面变化、位置异常或无法确认结束时，脚本保存现场并记录失败。只有尚未点击开始的入口超时才会在启动窗口内有限重试，最多准备三次；一旦尝试开始，即使未确认成功也不会当天重复创建记录。过了 07:01 不再补跑。

日常停用请在“晨跑与登录”点击“停用每日晨跑”，或双击个人脚本目录中的“停用每日晨跑.cmd”。要中断当前晨跑，可在安小信点击暂停；脚本监测到暂停后会停止位置发送并尝试结束它启动的记录。不要直接杀进程，否则无法保证结束按钮被点击。

修改速度和半径可编辑配置文件中的 speed_kmh、radius_m。源代码是项目根目录 morning_run.py。重新生成脚本 ZIP 使用 python build_morning.py。

## 验证范围（1.4.8）

2026 年 10 月 8 日已实测完整的 60 秒试跑：自动进入智慧运动、点击开始、以 12 km/h 发送 150 米半径的环形路线，自动暂停、长按结束并确认结果页。安小信显示 0.2 公里、00:01:07、平均 10.75 km/h；因低于 1 公里而显示无效。起止静止时间使应用显示的平均速度低于设定速度。脚本的时间窗口、模拟器选择、旧记录保护、结束按钮选择、异常和停止逻辑也通过自动测试。

2026 年 10 月 14 日已完成一次定时约一小时验证，日志确认自动开始和结束。已在官方模拟器验证约一小时的自动开始、路线发送和结束流程；平台对记录的最终判定仍需在原应用核对。 使用 logs 和 daily-state.json 核对各次任务，不把命令成功当作平台认可的证明。

## 立即试跑

在软件“晨跑与登录”页读取并确认起点，填写参数，点击“立即试跑 60 秒”即可；界面会先保存当前参数。外部命令“试跑晨跑60秒.cmd”或个人晨跑目录中的“试跑60秒.cmd”使用最后保存的配置。它会启动指定模拟器，按速度和半径试跑，结束后在 logs 下生成 trial-result.json；不会写入 daily-state.json，也不会阻止当天 07:00 的定时执行。

代码运行方式为：python morning_run.py --config 个人晨跑配置.json --trial-seconds 60。支持 1–300 秒。试跑期间按 Ctrl+C，或在安小信点击暂停，会停止位置发送并尝试结束本次启动的记录。已有记录会拒绝开始。

## 程序内的登录与运行按钮

在“晨跑与登录”手动填写账号和密码，点击“登录安小信”。如需晨跑遇到登录页时自动登录，勾选“为晨跑保存登录信息”并保存。账号密码通过 Windows DPAPI 加密到个人目录 login.dat，不会进入分发包或普通配置；换电脑或 Windows 用户需重新填写。取消勾选并保存可清除保存的信息。

原版账号密码页仅提交一次，确认已登录后继续进入跑步入口。密码错误、验证码、网络问题或无法识别的登录页会停止并保存结果。含中文、空格或字面 %s 的密码请在模拟器里手动登录。

“立即试跑 60 秒”已直接集成到程序，无需双击外部脚本。试跑、执行定时脚本、保存并启用每日晨跑都会先保存当前填写的参数。“执行今天的定时脚本”立即调用定时模式，仅在当天 06:50–07:01 会准备或启动；不会在其他时段补跑。“停止当前操作”停止该窗口启动的操作并尝试结束它自己创建的记录；不停止另由计划任务启动的进程。定时任务需要停止时，可在安小信内暂停，让任务监测到后清理结束。


一键停用：晨跑与登录页的按钮在任务运行时也可使用。取消当前登录、检查、试跑或定位操作，停用后续每日晨跑，等待本工具创建的记录结束与后台进程退出，然后关闭指定模拟器。配置和账号保留。若记录结束未确认，会报告原因并保留模拟器，需人工检查。再次点击试跑可恢复手动运行；定时晨跑需重新点击“保存并启用每日晨跑”。关闭软件不会自动停用每日任务。

智慧运动入口按 UI 层级寻找控件。点击后等待加载，重复点击间隔至少 20 秒；首页长期无响应时恢复入口一次。仅未尝试开始的入口超时可在启动窗口内最多准备三次。

## 后台查看与结果页

点击“查看后台画面”只读查看当前屏幕。停在“结束运动”结果页时，登录检查不会寻找不存在的密码页。需处理权限或验证码时，结束记录并关闭模拟器，取消后台选项，再启动可见窗口。60 秒试跑为可选验证。

## 结束后自动关闭安小信（1.4.8）

晨跑、60 秒试跑和一键跑步测试在确认本次记录结束后，先保存结果截图与日志，再自动关闭安小信，保留模拟器供下次使用。结束未确认或检测到仍打开的跑步页面时，保留安小信供检查。状态中的 app_closed 表示已确认应用进程退出；close_error 记录关闭失败原因。

1.4.8 修复已结束跑步页残留导致的旧记录误判：仅检查仍在任务中的活动，忽略 Android 的历史暂停引用和已结束活动。真正留在前台或后台任务中的跑步页仍会阻止自动开始、登录及关闭。
