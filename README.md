# 虚拟跑步 1.4.8 / Virtual Run

Windows 桌面路线模拟与 Android 定位测试工具，桌面版本为 **1.4.8**。通过官方 Android Emulator 和 ADB 操作测试界面，支持路线预览、起点准备、登录、短时试跑、每日定时任务、后台画面预览与一键停用。仓库同时包含独立 Android 模拟位置应用源码。

本仓库的源码树 **不包含安小信 APK、反编译代码、账号、运行日志、Android SDK、系统镜像或安装包**。安小信是独立第三方应用，不受本项目 MIT 许可证覆盖；需要自行取得有权使用的安装包。此工具适用于有授权的定位与界面测试，请遵守目标服务的规则，不将模拟轨迹冒充真实运动记录。

## 一键跑步测试

“跑步测试”只需填写速度、运动时长（1–3600 整数秒）和可选半径，点击“一键开始测试”。程序自动启动设置中的模拟器、进入运动页、读取当前 GPS、静止准备并自动开始和结束，兼容已有无窗口模拟器。无需输入经纬度或手动点击安小信开始、结束。

运动时长指发送移动轨迹的时间，准备和结束操作另需时间。若应用只有进入运动中才请求 GPS，程序先开启本次记录，等待有效定位后静止准备；这段准备也会计入应用记录。无法读取定位时不会使用默认坐标，会尝试结束它自己创建的记录，并报告错误。

每次点击创建一条新测试，停止按钮会结束本次记录；不再沿旧记录继续发送。已有手动记录或其他任务运行时不会接管。即时测试配置与每日晨跑配置分开保存，不改变每天的时间、起点或启用状态。首次登录、隐私、权限、验证码仍需完成一次；保存的自动登录设置可用于后续测试。

## 从源码启动 Windows 程序

需要 Windows 10/11 x64、Python 3.12 x64（包含 Tkinter），以及可用的硬件虚拟化。日常运行使用 Python 标准库，不需要安装 pip 依赖。

```powershell
git clone https://github.com/suiyuan1145/virtual_run.git
cd virtual_run
python -X utf8 android_location_test.py
```

也可双击 `启动虚拟跑步.cmd`。程序的“首次安装”可联网下载官方 Android Emulator、Platform Tools 和 Android 11 镜像；阅读并同意 SDK 许可后操作。已有环境可在“设置”中填写 SDK 和 AVD。

首次使用步骤：

1. 准备环境并启动模拟器，选择已连接的官方虚拟设备。
2. 点击“安装原版 APK”，选择自己取得的安小信安装包。本项目针对 2.0.5 / x86 安装进行过测试。
3. 手动完成隐私和权限提示，使用自己的账号登录，确认地图和起点。
4. 在“晨跑与登录”保存参数；短时试跑用于验证，可选执行。后台界面可通过“查看后台画面”只读查看。
5. 需要定时测试时启用每日任务：北京时间 06:55 准备，07:00–08:00 运行，默认 12 km/h、半径 150 米。

电脑须开机、网络可用且当前 Windows 用户已登录。关闭桌面界面不会停用每日任务；“一键停用”会取消当前操作、停用后续任务，并在确认结束自己创建的记录后关闭指定模拟器。遇到无法确认结束或已有手动记录时保留模拟器供检查。

无窗口模拟器通过 ADB 执行 Android 内部点击，不依赖桌面鼠标焦点。第一次登录和权限确认请使用可见窗口。

## 数据与验证边界

个人数据默认在 `%LOCALAPPDATA%\VirtualRunDesktop`，也可通过 `VIRTUAL_RUN_DATA_DIR` 指定。可选保存的账号密码使用 Windows DPAPI 加密，仅当前电脑的当前用户可解密；换电脑需要重新填写。个人配置、轨迹、截图和日志不应提交到仓库。

已进行短时自动开始、坐标发送、结束与停止流程测试。坐标命令成功、脚本结束成功，不代表第三方服务认可该记录；完整定时运行需要在使用者自己的环境中验证。

`morning/monitor_next_morning.py` 是只读检查工具，记录计划任务状态、发送进度和结束结果，不点击界面、不发送定位。可用以下命令安排次日 06:56、07:05、07:30、08:05 的一次性检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\morning\安排次日晨跑检查.ps1
```

报告默认保存到本仓库 `analysis/晨跑检查-日期/`，该目录已忽略。检查任务不是聊天通知，也不能证明第三方平台接受测试数据。

## 构建 Windows EXE

安装完整 Python 3.12 x64，并准备本机 Android SDK Platform Tools。构建脚本使用 Windows .NET Framework 自带的 C# 编译器，不要求安装 Visual Studio。

构建完整包前，将自己有权使用的原版 APK 放到 `analysis/input.apk`（Git 忽略）。构建包会包含该第三方 APK，发布生成的完整包前需自行确认相应分发许可。

```powershell
$env:ANDROID_SDK_ROOT = 'C:\Android\Sdk'
python build_windows.py
```

产物为 `dist/虚拟跑步-1.4.8-Windows.exe` 和完整 ZIP，包含本地 Python、ADB、说明、快捷方式与卸载器。历史 Windows 版本可在 [Releases 存档](https://github.com/suiyuan1145/virtual_run/releases/tag/legacy-windows-archive) 下载，存档不代表最新版本。图标已提供；仅重新生成图标时需要 Pillow。

## Android 源码

独立 Android 应用位于 `android/`，通过 Android 官方模拟位置接口发布测试坐标，不修改安小信或隐藏模拟位置标记。真机可能拒绝模拟定位；桌面模拟器测试结果不能推断真机兼容性。

构建需要 JDK 21、Android SDK Platform 35 和 Build Tools 36.0.0：

```powershell
python android/build_apk.py --sdk 'C:\Android\Sdk' --java 'C:\Java\jdk-21'
```

本机签名设置与密钥在 `android/signing/`，不会提交。完整说明见 [Android README](android/README.md)。

## 晨跑入口恢复与有限重试

晨跑不依赖事先进行 60 秒试跑。首页入口会等待加载，并在已启用自动登录时恢复登录一次。仅未尝试开始的导航超时可在当天启动窗口内有限重试，最多准备三次；开始意图在点击前保存，防止确认失败后创建重复记录。已有记录和用户取消仍会阻止自动开始，07:01 后不补跑。

可用 `python morning_run.py --config 个人晨跑配置.json --navigate-only` 验证导航。该模式只进入开始运动页，不点击开始、不发送定位，不修改每日状态；与晨跑共用互斥锁。

## 后台画面与登录识别

“晨跑与登录”中的“查看后台画面”显示设置中指定的官方模拟器，约每两秒刷新。预览为只读，不发送触摸或定位，不保存截图，不启动或重启设备，任务运行时也可查看。需要处理权限或其他提示时，先结束已有记录并关闭模拟器，取消“后台运行模拟器”，再重新启动。

登录按钮会复用已打开的首页或运动页面，包括“结束运动”结果页；识别到这些页面时不会重复提交密码。这只确认当前页面状态，不代表重新验证了服务器令牌。未知权限、验证码或其他页面仍需要人工处理。

## 当前验证范围

1.4.8 修复已结束页面的旧记录误判，支持结束后自动关闭安小信；关闭顺序、旧记录保护与失败处理已通过自动测试。此前已实测后台屏幕预览和结束结果页识别。已在官方模拟器验证约一小时的自动开始、路线发送和结束流程；平台对记录的最终判定仍需在原应用核对。

## 结束后自动关闭安小信（1.4.8）

晨跑、60 秒试跑和一键跑步测试在确认本次记录结束后，先保存结果截图与日志，再自动关闭安小信，保留模拟器供下次使用。结束未确认或检测到仍打开的跑步页面时，保留安小信供检查。状态中的 app_closed 表示已确认应用进程退出；close_error 记录关闭失败原因。

1.4.8 修复已结束跑步页残留导致的旧记录误判：仅检查仍在任务中的活动，忽略 Android 的历史暂停引用和已结束活动。真正留在前台或后台任务中的跑步页仍会阻止自动开始、登录及关闭。
